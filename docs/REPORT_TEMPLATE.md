# 潮汐忆体 · 周期汇报模板（TMA-CR v1）

> 每一轮退潮-涨潮结束后，插件在 `data/memory/reports/<年轮>.md` 生成一份汇报。
> 本文是**模板 + 填写规则 + 填好的示例**三合一，用于人工复核、月度复盘，以及对外发布时的证据材料。
> 设计原则：**只写可核对的事实，估算必须标注**；宁短勿长；每个数字都能在账本里找到出处。

- 适用范围：v2.0+，每次潮汐一轮（默认 3 天）
- 文件名：`reports/{ringId}.md`，如 `reports/a11.md`
- 生成者：`src/report/template.ts`（`renderReport(CycleReport)`，纯函数）
- 数据来源：`rings/<id>.json`、`ledgers/rings.jsonl`、`ledgers/forget.jsonl`、`distilled/` 五件套、模型 usage

## 第二部分：填写规则（写汇报的人/模型必须遵守）

1. **数字优先**：每个指标只能来自账本或 `rings/<id>.json` 的 `stats`；不得"感觉大概"。
2. **估算标注**：成本、压缩比的折算一律写"估算"；没有 usage 时不填，写 `n/a`。
3. **红线只有四条**：可回溯率 < 99%、承诺完整率 < 100%、孤儿指针 > 0、漂移率 > 5%。任一触发 → 综合判定至少 `watch`，不得写 `healthy`。
4. **降级必须显式**：`degraded=true` 时第 3 节必须写明原因与影响范围，第 8 节必须列为风险。
5. **不写情绪**：汇报不是给角色模型看的，是给人看的。禁止"我觉得""它可能记得"。
6. **可回溯**：第 9 节必须给出账本头与恢复命令，保证任何人能复核。
7. **单轮 ≤ 300 行**：超了就是该压缩的是汇报本身。

## 附：月度体检（每月 1 日，追加一份 `reports/MONTHLY_YYYY-MM.md`）

月度不重抄 12 节，只回答四个问题：

1. **忆体长胖了吗**：年轮数、总 token、平均压缩比、环比。
2. **有没有该记没记**：承诺完整率、检索失败样本（列出 query）。
3. **有没有记错**：漂移率、冲突条目、人工抽检结论。
4. **该不该死**：忆死风险判定（可回溯率、孤儿指针、归档完整性），以及恢复演练是否通过。
